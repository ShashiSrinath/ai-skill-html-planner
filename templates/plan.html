FEATURE PLAN

One-page checkout

Collapse the current three-step checkout into a single page with a persistent order summary, guest checkout, and express payment options. The goal is to cut cart abandonment from 68% to under 40% without adding new failure modes to payment capture.

In review 2026-08-11 Author: A. Reyes Owner: Payments squad

Context and problem

Checkout today spans three sequential pages — cart, shipping, then payment — each a full navigation. Analytics show the largest drop-off happens between the cart page and the shipping page, and a second, smaller drop-off at the payment step. Two structural problems drive most of the loss:

  • There is no guest checkout; every purchase requires creating an account first.
  • The order summary is hidden until the final step, so customers cannot confirm totals before committing.

A single-page layout with progressive disclosure addresses both: the summary stays visible, and account creation moves to an optional post-purchase prompt.

Goals

Reduce abandonment

Move the funnel from 68% abandonment to under 40% within two weeks of launch, measured against the same cohort definition used today.

Guest checkout

Let a customer complete a purchase with only an email address. Account creation is offered after the order is placed, never before.

Persistent summary

Show line items, shipping, and tax in a fixed panel on every step so the total is never a surprise at the end.

Express payments

Surface Apple Pay and Google Pay as one-tap options when the browser supports them, with card entry as the fallback path.

Implementation

  1. Consolidate the flow. Replace the three-page router with a single /checkout route that renders shipping, payment, and review as stacked sections with progressive disclosure.
  2. Add guest checkout. Treat the email field as the only required identity input. Defer the password and account-creation form until after a successful order.
  3. Persist a draft order. Write a draft order to the server on each completed section so a refresh or device switch does not lose progress.
  4. Wire express payments. Detect the Payment Request API and render the one-tap buttons only when available; keep the card form as the default.
  5. Instrument the funnel. Emit a checkout step event at each disclosure boundary so the abandonment metric can be compared before and after launch.

Decision

Use a single-page layout with progressive disclosure rather than a multi-step wizard. A wizard keeps the same number of navigations as today and does not solve the hidden-summary problem. A single page keeps the summary visible and lets express payment buttons act on the whole order at once.

Open questions

Should the post-purchase account prompt be a modal or an inline panel? A modal risks interrupting the confirmation screen; an inline panel is quieter but easier to ignore.

Which payment providers must be supported for the EU launch? The current gateway covers card and the two express wallets, but regional methods such as iDEAL and Klarna are not yet contracted.

Code

The form component owns the disclosure state and hands a validated payload to the order service. The validator below is the single source of truth for what may be submitted. 

export function CheckoutForm({ cart, onComplete }: Props) {
  const [state, setState] = useState<CheckoutState>("idle");

  const submit = async (event: FormEvent) => {
    event.preventDefault();
    setState("processing");
    const order = await createOrder(cart);
    setState(order.ok ? "done" : "error");
    if (order.ok) onComplete(order.id);
  };

  return (
    <form onSubmit={submit} aria-busy={state === "processing"}>
      <fieldset disabled={state === "processing"}>
        <label htmlFor="email">Email</label>
        <input id="email" type="email" required />
      </fieldset>
    </form>
  );
}
export function validateCheckout(input: CheckoutInput): Result {
  const errors: string[] = [];
  if (!isEmail(input.email)) errors.push("email");
  if (input.items.length === 0) errors.push("items");
  if (input.total <= 0) errors.push("total");
  return errors.length === 0 ? { ok: true } : { ok: false, errors };
}
