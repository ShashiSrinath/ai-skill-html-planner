ARCHITECTURE DECISION RECORD

ADR-014 — Migrate the order store to Postgres

Replace the document store backing order history with a relational Postgres database, adopting a schema-first model and explicit transactions for order lifecycle state.

Accepted 2026-08-11 Author: M. Okafor Status: supersedes ADR-009

Context

Order history is currently stored as JSON documents in a key-value store. Reads are fast, but the service has grown to need cross-order queries — revenue by region, refund reconciliation, and per-customer order lists — that the document model cannot express without client-side aggregation. Two incidents this quarter were caused by partial writes that left an order in an inconsistent state, because the store has no native transactions across related records.

The team is small and already runs Postgres for the catalog. Reusing the same engine removes an operational surface rather than adding one.

Decision

We will migrate order history to Postgres 16, modeled as a normalized schema with an orders table, an order_items table, and a order_events table for state transitions. All writes that touch more than one row run inside a single transaction. The document store is retired once the migration backfill is verified.

Adopt a relational model with explicit transactions over a document model with eventual consistency. Correctness of order state is a hard requirement; the query flexibility is a direct benefit.

Consequences

  • Cross-order analytics queries become expressible in SQL.
  • Transactions guarantee an order is never left half-written.
  • One database engine across catalog and orders reduces operational burden.
  • Schema migrations must be managed and reviewed; the document store had none.
  • Write throughput is lower than the key-value store; load tests must confirm headroom.
  • The backfill is a one-time, irreversible data move that needs a dry run.

Alternatives considered

Keep the document store
Lowest effort, but leaves the query and consistency problems unsolved. Rejected because the reconciliation incidents recurred twice in one quarter.
Add a read replica with a search index
Solves read queries but not the write-consistency gap. Rejected as a partial fix that adds a second system.
Migrate to Postgres
Chosen. Reuses existing operational knowledge, adds transactions, and makes the required queries straightforward.
